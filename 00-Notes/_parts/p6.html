并发、临界区与 ISR 三范式

多个任务 + 多个中断，会同时碰同一块内存。RTOS 提供的"保护手段"在 CM0+ 上和 M3/M4 有本质区别，这是抄教程最容易抄错的地方。

知识点 9.1临界区是可嵌套的，靠一个计数器

裸机时代"关中断/开中断"只能成对出现，多层调用就乱了。FreeRTOS 用一个计数解决：

void vPortEnterCritical( void )   /* port.c:262 */
{
    portDISABLE_INTERRUPTS();      /* cpsid i */
    uxCriticalNesting++;           /* 嵌套层数 +1 */
}
void vPortExitCritical( void )    /* port.c:271 */
{
    configASSERT( uxCriticalNesting );
    uxCriticalNesting--;
    if( uxCriticalNesting == 0 )   /* ★只有回到 0 才真正开中断 */
    {
        portENABLE_INTERRUPTS();   /* cpsie i */
    }
}

调试时把 uxCriticalNesting 加到 Watch 窗口：稳态必须是 0。长期不为 0 说明某处漏了配对的 taskEXIT_CRITICAL()，系统时间会变慢（中断开不回来，tick 进不来）。

ISR → 任务的三种标准范式

中断里"做决策、做重活"是禁忌。正确姿势只有三种，按开销从大到小：

ISR 里的铁律
  • 只能用名字带 ...FromISR 的 API：xQueueSendFromISR / xSemaphoreGiveFromISR / xTaskNotifyFromISR。
  • 唤醒标志变量必须初始化：BaseType_t xHigherPriorityTaskWoken = pdFALSE;
  • 退出前一定要 portYIELD_FROM_ISR(xHigherPriorityTaskWoken); —— 否则"被唤醒的高优先级任务"要等到下一次 tick 才轮到。
  • ISR 里禁止：vTaskDelay、HAL_Delay、Flash 写、长 printf。
  • CM0+ 的 ARM_CM0 端口没有优先级校验函数，所以你在 ISR 里误用非 FromISR 版本 API 不会触发断言，而是偶发数据错乱 —— 只能靠纪律。

应用：把裸机程序变成多任务

回到你的工程。原来它是一段裸机程序，现在是 2 个任务。差别不只是"能同时做两件事"，而是时间的管理权从"你排的循环顺序"变成了"内核按优先级调度"。

四个可复用的做法

做法 1按"职责"切任务，不按"外设"切

❌ 错误：UartTask / TimTask / GpioTask（这是把中断搬到任务里）。
✅ 正确：SensorTask（采集+滤波）、JudgeTask（安全判定，优先级最高）、CommTask（协议收发）、LogTask（打印/存储）、MgrTask（喂狗+低功耗）。

做法 2优先级只有 3 ~ 4 档，安全最高

本工程实测可用的分法：安全判定 3 > 业务/通信 2 > 日志/显示 1 > 空闲 0。别用优先级去解决"谁先谁后"的同步问题，那应该用队列/信号量。

做法 3栈大小用"水位"倒推，不用猜

  • 单位是字：128 = 512 字节；
  • 含 printf / vTaskList（内部用 sprintf）的任务给 256 字；
  • 用 uxTaskGetStackHighWaterMark() 看剩余，留 30% 余量再定稿；
  • 本工程实测：led 任务剩余 118 字、log 任务剩余 185 字（都在安全区）。

做法 4周期任务用 vTaskDelayUntil，别用 vTaskDelay

写法含义累积漂移
vTaskDelay(250)从"现在"开始睡 250ms会漂移（执行时间被累加进去）
vTaskDelayUntil(&last, 250)睡到"上次唤醒时刻 + 250ms"不漂移（以起点为基准）

你的 50ms 采样、1 秒打印、定时喂狗都属于这类，一律用 vTaskDelayUntil。
