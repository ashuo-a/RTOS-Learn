01

上电那一刻发生了什么

按下复位键，CPU 内部没有"操作系统"，也没有"main 函数"。它只做一件事：从地址 0x00000000 处取两个字。而 PY32C882 的 Flash 被映射到 0x08000000，所以实际读的是 0x08000000。

知识点 1.1复位不是"从 0 开始"，而是"从向量表开始"

向量表 = 一个 48 字的数组（Cortex-M0+），每个字是一个地址。CPU 硬编码使用前两个：[0] → MSP、[1] → PC。字段顺序不能改，改了上电就跑飞。

知识点 1.2两个"堆/栈"完全是两回事

名字在哪定义谁用本工程实测
Stack_Size（MSP 主栈）启动文件 startup_py32c882xx.s中断、异常、启动代码0x800 = 2 KB（移植时从 0x400 提上来的）
Heap_Size同上malloc()（MicroLIB）0x200 = 512 B，FreeRTOS 根本不用它
configTOTAL_HEAP_SIZEFreeRTOSConfig.hFreeRTOS 的 pvPortMalloc8192 B，是 heap_4.c 里一个 静态数组（进 .bss）
任务栈 ×NxTaskCreate() 第 3 个参数各任务自己（走 PSP）128 字 = 512 B（单位是"字"！）

最容易搞错的一点：FreeRTOS 的内存不是从启动文件的 Heap_Size 里来的。heap_4.c 里有一个 static uint8_t ucHeap[configTOTAL_HEAP_SIZE]，它作为普通全局变量进 .bss，跟着 SRAM 一起被清零。两者互不相干。

02

CPU 的 16 个寄存器和两个栈

理解任务切换，只需要搞清"现场"是什么。现场 = 16 个寄存器的值。把它们原样存下来、再把另一个任务上次存的值装回去，就是一次上下文切换。

知识点 2.1SP 只有一个名字，却有两个实体

汇编里写 SP，CPU 内部其实有两个寄存器 MSP / PSP，由 CONTROL[1]（SPSEL）决定当前用哪个。所以：

  • mrs r0, psp —— 读出"另一个"栈指针，是 FreeRTOS 里最关键的一条指令之一；
  • Handler 模式下硬件强制走 MSP，写 SPSEL 也无效 —— 这条保证了中断安全。
